# Quine–McCluskey 알고리즘 구현

과제제안서 `Implementation_of_Quine_McCluskey_algorithm_2023_v4.pdf`를 바탕으로 기존 C++ 구현을 점검하고 수정한 프로젝트다.

## 1. 프로젝트 목표

- 양의 입력 비트 수와 minterm(`m`), don't-care(`d`) 목록을 받아 Boolean 함수를 SOP(Sum of Products, 곱의 합) 형태로 최소화한다.
- 모든 `m`에서 출력이 1이고, 입력에 없는 조합에서는 0이 되도록 한다. `d`의 출력은 0 또는 1 중 어느 쪽이어도 된다.
- PI(Prime Implicant, 주항)를 생성하고 PI chart로 필요한 항을 선택한다. 수정본은 항 개수만 줄이는 대신 공유 NOT 게이트를 포함한 트랜지스터 수를 최소화한다.
- 기본 파일명 `input_minterm.txt`, `result.txt`와 과제의 출력 형식을 유지한다.
- C++ 표준 라이브러리만 사용하고 단일 스레드로 실행한다. 코드에는 한국어 주석을 사용한다.

## 2. QM 알고리즘 간단 설명

1. 입력 준비: `m`과 `d`를 함께 결합 후보에 넣는다. 같은 종류의 중복 입력은 제거한다.
2. 반복 결합: `-`의 위치가 같고, 나머지 비트 중 정확히 하나만 `0`/`1`로 다른 두 항을 결합한다. 다른 비트를 `-`로 바꾼다. 예를 들어 `0100`과 `0101`은 `010-`가 된다.
3. PI 수집: 현재 단계에서 더 결합되지 않은 항을 PI로 남긴다. 새 항의 중복을 제거하고 결합을 반복한다.
4. PI chart 작성: 행은 PI, 열은 반드시 덮어야 하는 `m`이다. `d`는 항의 확장을 허용하지만 최종적으로 덮을 의무는 없다. `d`만 덮는 PI는 제외한다.
5. 필수 PI 선택: 특정 `m`을 덮는 PI가 하나뿐이면 그 PI를 먼저 선택한다.
6. 최소 비용 커버 탐색: 아직 덮이지 않은 `m`의 후보 PI들을 분기 한정법으로 탐색한다. 탐욕 선택은 초기 상한으로만 사용한다. 후보 수가 적은 열부터 탐색하고, 최선 비용보다 낮아질 수 없는 분기는 제외한다.
7. 출력: 선택된 항을 사전순으로 기록하고 마지막 줄에 비용을 기록한다.

유효한 항은 리터럴을 제거해 PI로 확장해도 AND 및 NOT 비용이 늘지 않는다. 따라서 PI 조합을 정확하게 탐색하면 아래 비용 모델의 최소 비용 SOP를 찾을 수 있다. 최소 비용 해가 여러 개라면 그중 하나를 출력하며, 항 개수나 리터럴 수에 대한 별도 동률 최적화는 하지 않는다.

### 비용 계산

제안서의 인버터·AND·OR 2단 논리 회로 모델을 사용한다.

| 구성 | 트랜지스터 수 |
| --- | ---: |
| NOT | 반전이 필요한 입력 변수마다 2개, 모든 항이 공유 |
| k입력 AND (`k >= 2`) | 항마다 `2k + 2`개 |
| t입력 OR (`t >= 2`) | 전체 출력에 `2t + 2`개 |
| 1리터럴 항 | AND 없이 배선으로 연결 |
| 항이 하나인 SOP | OR 생략 |
| 상수 0 또는 1 | 논리 게이트 비용 0으로 처리 |

여기서 `k`는 해당 항의 `0`/`1` 개수다. 예를 들어 `A'BC' + C'DEF`는 NOT 4개, AND 8개와 10개, OR 6개로 합계 28개다. 제안서에는 상수 및 1리터럴 회로의 별도 예가 없어, 불필요한 게이트를 생략하는 위 규칙을 명시적으로 적용했다.

## 3. 구현 시 유의 사항

### 입력과 출력

입력 첫 유효 줄은 양의 비트 수이며, 이후 각 줄은 `m` 또는 `d`와 정확히 그 길이의 이진 문자열이다.

```text
4
d 0000
m 0100
m 0101
m 0110
m 1001
m 1010
d 0111
d 1101
d 1111
```

이 예의 출력은 다음과 같다.

```text
01--
1-01
1010
Cost (# of transistors): 40
```

- 공백·빈 줄·CRLF/LF 줄바꿈·첫 줄의 UTF-8 BOM·`//` 뒤 설명을 허용한다. 마지막 줄에 줄바꿈이 없어도 된다.
- 동일한 `m` 또는 `d`의 중복은 제거한다. 같은 비트열에 `m`과 `d`가 모두 지정되면 모호한 입력으로 보고 오류를 반환한다.
- 잘못된 비트 수, 비트 길이, 구분자, 이진 문자, 추가 토큰, 파일 열기·쓰기 실패를 검사한다. 성공은 종료 코드 0, 오류는 1이며 오류 내용은 표준 오류로 출력한다.
- `m`이 없으면 상수 0을 선택하여 항 없이 `Cost (# of transistors): 0`만 쓴다. 전체 공간을 덮는 항은 비트 수만큼의 `-`로 출력한다.
- 문자열 길이는 실제 비트 수만 사용한다. 문자열 종료 문자 `NUL`은 결과에 기록하지 않는다.
- 입력 읽기와 계산에 성공한 뒤 출력 파일을 연다. 출력 대상으로 이미 존재하는 파일을 지정하면 그 내용을 교체한다.

### 결합 및 최적화의 정확성

- `d`를 결합에서 제외하면 가능한 간소화를 놓치고, `d`를 필수 커버 대상으로 취급하면 불필요한 항을 선택한다.
- 결합 여부와 결과 중복을 명확하게 관리하고, 결합된 두 원본 항을 모두 사용 처리해야 한다.
- NOT는 같은 변수의 반전 신호를 공유한다. PI별 NOT 비용을 단순 합산하면 잘못된 비용이 된다.
- 가장 많은 `m`을 덮는 PI를 반복해서 고르는 방법만으로는 최소 비용이 보장되지 않는다.
- 수정본의 탐색 하한은 각 미커버 열의 최소 추가 비용 중 최댓값이다. 여러 열을 한 PI가 덮을 수 있으므로 이를 합산하면 안전한 하한이 아니다.
- 문자열 기반으로 32/64비트 정수의 변수 수 제한을 피한다. 다만 QM의 PI 수와 정확 커버 탐색량은 입력에 따라 지수적으로 증가하므로 실행 시간·메모리·재귀 깊이의 현실적 제한은 있다.

## 4. 보완 또는 개선 사항

### 수정본에 반영한 사항

| 기존 구현의 문제 또는 취약점 | 수정 내용 |
| --- | --- |
| `while (!eof())`와 고정 길이 문자 버퍼 때문에 마지막 줄 및 실패한 읽기를 데이터로 처리할 수 있음 | `while (getline(...))`와 행별 검증으로 교체 |
| 비트 수보다 한 글자 더 처리하여 출력에 `NUL`이 포함됨 | 실제 비트열만 `std::string`에 저장하고 출력 |
| 결합 조건·사용 표시·중복 제거가 여러 수동 인덱스에 의존함 | 같은 패턴에서 한 비트만 바꾼 상대를 찾고 `set`으로 중복 제거 |
| 전역 결과와 수동 `new[]`/`delete[]` 관리에 의존함 | 지역 상태와 표준 컨테이너로 소유권 및 메모리 관리 |
| 초기화 범위 `fill(ox, ox + (row - 1), ...)`가 마지막 원소를 제외함 | 해당 배열을 없애고 집합으로 결합 여부 관리 |
| 최대 커버 수 기준의 탐욕 선택만 수행함 | 필수 PI + 정확한 분기 한정 탐색으로 최소 트랜지스터 비용 선택 |
| 항이 하나이면 AND 비용을 누락하고, 여러 항에서는 1리터럴도 AND로 계산함 | 항별 AND, 전체 OR, 공유 NOT를 각각 정확히 계산 |
| 입력 형식·파일 오류 검사가 부족함 | 오류 메시지 및 종료 코드 제공 |

### 추가 개선 방향

- PI chart를 동적 비트 집합으로 표현해 커버 검사와 복사를 줄일 수 있다.
- 같은 `-` 패턴별 해시 구조를 이용해 PI 생성 시 문자열 비교 비용을 줄일 수 있다.
- 열 지배 관계 및 탐색 상태 재사용을 도입할 수 있다. 행 지배를 적용할 때는 공유 NOT와 OR 비용까지 고려해야 하므로 항별 비용만 비교해 제거하면 안 된다.
- PI 개수·탐색 노드 수·시간·메모리를 별도로 기록하면 어려운 입력을 분석하기 쉽다.
- 큰 문제에 시간 제한이나 근사 모드를 추가할 경우, 최적성 검증이 끝난 결과와 구분해서 표시해야 한다. 현재 수정본은 임의의 시간 제한이나 근사 결과 반환을 넣지 않는다.

기본 실행은 현재 작업 폴더의 `input_minterm.txt`를 읽어 `result.txt`를 작성한다. 기존 결과를 보존하려면 출력 경로를 지정한다.

제공된 입력에 대한 수정본의 출력은 `result2.txt`에 저장했다.

```text
---001
--10-1
-0--0-
-1011-
001--1
1--010
Cost (# of transistors): 78
```

기존 `result.txt`도 표시된 비용은 78이다. 따라서 이 입력에서 비용이 줄었다고 주장하지 않는다. 수정본은 불필요한 `NUL`을 제거하고, 최소 비용을 검증한 유효한 해를 출력한다.
